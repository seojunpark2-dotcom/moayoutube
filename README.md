# 모아유튭

## 현재 버전: 2.2.0 · 사이트 버튼으로 로컬 프로그램 실행

기존 Render 다운로드 방식에서 **사용자별 로컬 실행 프로그램** 방식으로 변경했습니다. [Windows 실행 ZIP](https://github.com/seojunpark2-dotcom/moayoutube-local/releases/latest/download/moayoutube-local-windows-x64.zip)을 압축 해제한 뒤 **모아유튭 실행.cmd**를 실행하세요. 프로그램에 Node.js·Python·FFmpeg가 포함되며 자동으로 로컬 화면이 열립니다. 각 PC의 인터넷으로 원본을 받아 MP3·MP4를 생성합니다.

공개 사이트는 로컬 프로그램에 연결하는 화면으로 사용합니다. 아래 v1.x의 Render/Cobalt 설명은 이전 구조의 기록입니다. 현재 설치·개발·배포 안내는 **[LOCAL-APP.md](LOCAL-APP.md)**를 먼저 확인하세요. 로컬 실행으로 모든 영상의 다운로드가 보장되는 것은 아니며 접근 제한은 우회하지 않습니다.

ZIP 안의 **사이트 연결 등록.cmd**를 한 번 실행하면 공개 사이트의 **링크 확인** 버튼이 프로그램을 열고 조회를 이어갑니다. 브라우저의 프로그램 열기 확인은 허용해야 합니다. 관리자 권한이나 로그인 시 자동 실행은 사용하지 않습니다. 폴더를 이동하면 다시 등록하고, 연결 삭제는 **사이트 연결 해제.cmd**를 실행하세요.

한국어 영상·음원 다운로드 웹앱. Next.js + TypeScript + Tailwind CSS 프런트엔드와 별도 Node.js/Express API, FFmpeg 자식 프로세스로 구성됩니다. 데이터베이스·회원가입·유료 API가 없습니다.

v1.4.0부터 Render용 `Dockerfile.api`에는 Cobalt 서버가 포함됩니다. 새 서비스나 다운로드 API 키 없이 같은 Render 주소에서 실행하며, Vercel 화면 주소도 유지합니다. Windows의 `npm run dev`는 기존 yt-dlp 방식을 사용합니다. 배포·원복·제한은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요. Cobalt 연결로 YouTube의 서버 접근 제한이 자동 해결되는 것은 아니며 실제 다운로드 성공 여부를 별도로 확인해야 합니다.

v1.5.0: 공개 UI는 MP3·MP4를 제공하며 링크 확인 전에 형식을 선택합니다. MP3는 96/128/256/320kbps, 영상 요청 화질은 144/360/480/720/1080p입니다. 요청 화질은 가능한 화질 목록이 아니며, 조회 후 확인된 실제 원본 화질만 다운로드 결과에 표시합니다. Cobalt 원본 조회는 선택한 형식·화질 한 번으로 줄였습니다. CNVMP3의 서버나 비공개 API를 연결한 것은 아닙니다.

## 시작하기 (Windows / macOS / Linux)

Node.js 24.x, Python 3.10 이상과 pip가 필요합니다. FFmpeg·FFprobe 바이너리는 npm 패키지로 프로젝트 안에 설치되므로 전역 설치가 필요 없습니다.

```sh
npm install
npm run setup
npm run setup:youtube
npm run dev
```

브라우저에서 **http://localhost:3000** 에 접속합니다. `샘플로 체험하기`를 누르면 직접 생성한 8초짜리 720p 컬러 패턴과 사인파 음원을 분석합니다. MP4와 MP3를 실제 변환·저장할 수 있습니다. 종료는 터미널에서 Ctrl+C입니다. `npm run setup`은 테스트 샘플을 다시 생성합니다. npm 11에서 설치 스크립트 차단 안내가 나오면 `npm install-scripts approve ffmpeg-static`과 `npm rebuild ffmpeg-static`을 실행하세요.

```sh
npm test
npm run typecheck
# Microsoft Edge 설치 환경에서 PC·모바일 브라우저 기능 검사
node scripts/browser-check.mjs
npm run build
npm start
```

빌드 후 `npm start`는 프런트엔드와 API를 함께 실행합니다. 개발 서버는 기기 내부의 루프백 주소에 바인딩됩니다. 모바일 크기 반응형 화면을 지원하지만 휴대전화에서 같은 LAN으로 직접 접속하려면 서버 바인딩과 방화벽 설정이 별도로 필요합니다.

## 지원 범위와 권한 확인

- **YouTube:** 현재 화면은 MP4 영상과 MP3 음원 추출을 제공합니다. Render 컨테이너는 Cobalt, 기본 로컬 실행은 yt-dlp를 사용하고 공식 oEmbed로 제목·채널을 조회합니다. 반환된 실제 1080p 이하 화질만 다운로드 결과에 표시합니다. 인증·DRM·연령·지역·봇 확인 등 접근 제한은 우회하지 않고 오류로 안내하며 라이브·공개 예정 영상은 지원하지 않습니다. 긴 영상은 파일 크기와 처리 예산 범위 안에서 지원합니다. 원본 접근이 거절되면 새 파일을 생성할 수 없습니다.
- **승인 소스:** 관리자가 실제 소유·허가·라이선스 근거를 확인하고 등록한 HTTPS 직접 영상 파일만 처리합니다. 이용자의 권한 체크박스로 임의의 플랫폼을 허용하지 않습니다.
- **샘플:** `.data/library/studio.mp4`는 FFmpeg `testsrc2`와 `sine`로 직접 생성한 원본이며 이 프로젝트에서 다운로드·변환을 허용합니다. 샘플 URL `https://sample.moadrop.local/studio-loop.mp4`는 내부 카탈로그 식별자여서 외부 DNS 요청을 하지 않습니다.
- **화질:** 실제 원본 해상도를 FFprobe로 검사합니다. 표시된 낮은 화질은 원본에서 축소 인코딩한 결과이며 플랫폼에 별도로 존재하는 스트림이라고 주장하지 않습니다. 원본보다 높은 화질은 차단합니다.
- 비트레이트를 높여도 원본에 없는 소리의 정보가 복원되지 않습니다. 음성이 없는 영상 또는 변환 허가가 없는 소스는 음원 탭이 비활성화됩니다.
- yt-dlp 2026.10.21을 `.tools/python`에 프로젝트 전용으로 설치합니다. 사용자 설정·쿠키·로그인·프록시·토큰 파일을 읽지 않습니다. JS 런타임은 설치된 Node.js를 사용하고, 원격 런타임 구성요소를 자동으로 내려받지 않습니다. yt-dlp의 PyPI 소스/휠은 Unlicense이며, 기본 의존성은 각자의 라이선스를 따릅니다. 출처: [yt-dlp 공식 저장소](https://github.com/yt-dlp/yt-dlp).

## 관리자가 허용된 외부 영상을 추가하기

현재 작업 환경에는 MDN의 CC0 공개 샘플도 등록되어 있습니다. 아래 주소를 사이트에 붙여넣어 외부 소스 처리를 체험할 수 있습니다. 새로 설치한 환경에서는 같은 명령으로 먼저 등록하세요.

```sh
npm run register -- "https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4" "꽃잎 사이로 · CC0 공개 샘플" "MDN Web Docs" "CC0 · https://github.com/mdn/interactive-examples/tree/main/live-examples/media/cc0-videos" allow-convert
```

서버 운영자가 직접 권한을 확인한 후 로컬 터미널에서 실행합니다. 이 기능은 공개 웹 API로 노출되지 않습니다. 라이선스의 재배포·변환 허용 여부도 확인해야 합니다.

```sh
npm run register -- "https://your-domain.example/owned-video.mp4" "영상 제목" "제작자" "소유권 또는 이용 허락의 근거" allow-convert
```

변환이 허용되지 않으면 마지막 인수를 `download-only`로 지정하세요. MP4는 H.264/AAC·동일 해상도이면 원본 코덱을 복사해 합치고, 비호환 코덱이나 화질 변경 시 재인코딩하므로 **영상의 재인코딩이 허용된 소스만** 등록해야 합니다. `download-only`는 음원 추출 금지를 의미합니다. 파일은 등록 시 한 번 내려받아 검사하고 로컬 승인 목록에 저장합니다. 이후 사용자가 동일 URL을 입력하면 승인된 로컬 복사본을 처리합니다. 삭제·권한 회수는 서버를 종료한 뒤 `.data/library.json`에서 항목과 해당 `.data/library/`, `.data/thumbs/` 파일을 제거하고 재실행합니다. JSON을 편집하거나 등록 CLI를 실행하는 동안 여러 관리자 작업을 동시에 수행하지 마세요.

## 보안·개인정보·제한

- 임의의 사용자 URL은 가져오지 않습니다. YouTube는 엄격하게 파싱한 11자리 영상 ID로 고정된 YouTube 주소만 분석합니다. 실제 파일은 `.googlevideo.com`의 HTTPS 직접 스트림만 내려받고, 매 연결에 공인 IP 검사·DNS 고정·리다이렉트 차단을 적용합니다. HTML 임베드는 렌더링하지 않습니다.
- 관리자 등록도 HTTPS, 인증정보·별도 포트 금지, 공인 IP 검사, IPv4-mapped IPv6 검사, DNS 조회 결과를 실제 연결에 고정하여 DNS 재바인딩 방지, 리다이렉트 금지를 적용합니다.
- FFmpeg/FFprobe는 네트워크 프로토콜을 허용하지 않습니다. 서버가 구성한 경로와 인수만 전달하며 셸을 실행하지 않습니다.
- 영상 길이 제한 없음, 원본(분리 영상+음원 합계)·결과 각각 최대 2GB, 동시에 2개 변환, 파일 수신 최대 60분·변환 최대 60분·작업 전체 최대 120분, 관리자 등록도 스트리밍 수신, 공식 메타데이터 요청 10초·YouTube 스트림 분석 45초 제한입니다. 초과하면 오류를 표시합니다.
- 변환 요청 분당 IP당 8회, 일반 API 분당 IP당 240회, 완료 결과를 포함한 작업은 최대 20개로 제한합니다. 대기열 대신 혼잡 오류를 반환합니다.
- 작업 UUID는 파일 접근 토큰입니다. 완료 파일은 최대 24시간·총 2GiB·18개 안에서 보관하며 예산 초과 시 오래된 결과부터 삭제합니다. 실패 작업은 약 15분 뒤 정리합니다. 같은 디스크에서 프로세스를 재시작하면 검증된 완료 결과를 복원하고 중단된 임시 작업은 삭제합니다. Render의 임시 디스크는 재배포·수면 후 보존을 보장하지 않으므로 장기 보존에는 별도 영속 디스크가 필요합니다. 승인 원본은 관리자가 삭제할 때까지 보관합니다.
- 사용자 입력 URL·IP를 영구 저장하는 애플리케이션 로그나 분석 도구가 없습니다. 속도 제한을 위한 IP 카운터와 작업 상태는 메모리에만 보관합니다. YouTube 스트림 정보는 최대 40개·5분간 메모리에 캐시하며 디스크에 저장하지 않습니다. 내려받은 YouTube 원본과 변환 결과는 작업별 임시 폴더에서 함께 자동 삭제합니다. 서버 액세스 로그나 호스팅 로그는 배포 환경에서 별도 관리하세요. YouTube 조회는 해당 서비스로 영상 ID를 전송하며 썸네일 요청은 브라우저에서 YouTube 이미지 서버로 전송됩니다.
- 로그인 없는 단일 서버 MVP입니다. 인터넷 공개 운영에는 TLS, 서버 프로세스 격리·리소스 제한, 신뢰 프록시 설정, 외부 트래픽 제한, 디스크 모니터링, 관리자의 권한 증빙 점검이 필요합니다.

## 배포 구조

**GitHub → Vercel 연결 및 별도 변환 서버 실행 절차는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.** `vercel.json`, `.env.example`, `Dockerfile.api`가 포함되어 있습니다. 사이트 화면과 변환 API는 각각 배포해야 실제 다운로드가 동작합니다.

프런트엔드는 `app/`, API는 `server/index.mjs`, 변환 프로세스는 `server/worker.mjs`, 원본 등록은 `scripts/register.mjs`입니다. `.data/`는 git에서 제외합니다.

Vercel에는 Next.js 프런트엔드를 배포하고 `API_ORIGIN`을 별도 지속 실행 Node.js 서버의 HTTPS 주소로 빌드 시 지정하세요. 완성 파일은 해당 원점에서 직접 다운로드합니다. API 서버에는 `WEB_ORIGIN`을 실제 프런트엔드 도메인으로 설정합니다. 개발 기본값은 API `http://127.0.0.1:4000`, 웹 `http://localhost:3000`입니다. `API_PORT`(또는 `PORT`)로 API 포트를 변경할 수 있습니다. 공개 배포 시 API를 신뢰할 수 있는 리버스 프록시 뒤에 두고 `API_HOST=0.0.0.0`으로 수신하도록 설정하세요. 장시간 FFmpeg 프로세스와 로컬 임시 파일을 사용하는 API 전체를 Vercel의 일반 서버리스 함수에 그대로 올리는 구조는 아닙니다. API 서버는 영구 디스크가 있는 컨테이너·VM에서 1개 인스턴스로 운영합니다. 다중 인스턴스에는 공유 작업 저장소·큐·파일 저장소가 추가로 필요합니다.

## 오픈소스

Next.js: MIT, React: MIT, Express: MIT. `ffmpeg-static` 패키지와 포함된 FFmpeg 바이너리의 라이선스는 구분해야 하며, 실제 설치된 FFmpeg의 `-L` 결과는 GNU GPL v3 또는 이후 버전입니다. 배포·재배포 시 설치된 패키지 라이선스와 `ffmpeg -L`/빌드 옵션을 확인하고 필요한 고지·소스 제공 의무를 이행하세요. ffprobe-static 바이너리도 같은 방식으로 검토하세요.

참고: [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [FFmpeg 사용법](https://ffmpeg.org/ffmpeg.html), [FFmpeg 법적 고지](https://ffmpeg.org/legal.html), [YouTube 서비스 약관](https://www.youtube.com/static?template=terms).

YouTube 도구 재설치: `npm run setup:youtube`. Python 경로가 다른 경우 `PYTHON_BIN`에 실행 파일 경로를 지정하세요. 배포 API 컨테이너에도 Python·Node.js 및 `.tools/python` 의존성이 필요합니다. YouTube 추출 방식은 플랫폼 변경에 영향을 받으므로 도구 업데이트 후에는 실제 영상으로 재검증하세요.

## 다운로드 속도·재시도 (v1.1.1)

YouTube 원본은 8MiB 단위 HTTP Range 요청을 파일당 최대 8개 병렬 연결로 받습니다(v1.3.1). 첫 구간도 나머지 구간과 함께 수신하여 초기 직렬 대기를 없앴습니다. 분리된 영상과 음원도 동시에 수신하며, 작업 2개 제한에서 원본 연결은 합계 최대 32개입니다. Range 미지원 서버는 단일 연결 스트리밍으로 자동 전환하며, 모든 원본은 메모리 전체 버퍼 대신 임시 파일에 직접 기록합니다. MP4 호환 코덱·해상도에서는 재인코딩 없이 합쳐 처리 시간을 줄입니다. 원본 서버·인터넷 회선이 병목이면 병렬 연결을 늘려도 빨라지지 않을 수 있습니다.

진행 중인 전송을 60초 만에 중단하던 고정 시간 제한을 제거했습니다. 45초 동안 새 데이터가 없는 연결만 재시도하고, 부분 요청은 이미 받은 위치부터 최대 2회 이어받기를 시도합니다. 접근 거절(401/403)은 우회하거나 재시도하지 않습니다. 전체 수신·변환 상한은 유지하며, 브라우저 상태 확인은 최대 122분입니다. 화면에 받은 용량·평균 전송 속도·예상 남은 시간·수신/합치기/변환 단계를 표시합니다. 속도는 실제 네트워크와 원본 서버 상태에 따라 달라집니다.

## 가장 빠르게 받기 (v1.2.0)

현재 화면은 MP3·MP4만 제공합니다. 이전 API의 M4A·OPUS·원본 음원 처리는 호환성을 위해 서버에 남아 있으나 화면 메뉴에서는 제외했습니다. MP3는 재인코딩이 필요하며 비트레이트를 높여도 원본 이상의 음질이 복원되지는 않습니다.

같은 소스·형식·실제 출력 옵션의 동시 요청은 하나의 작업을 공유합니다. 완료 결과는 최대 24시간 보관 예산 안에서 분석 전에 확인하므로, 기존 파일이 있으면 YouTube 원본 조회와 변환을 생략합니다. 화질이나 비트레이트가 다르면 별도 파일입니다. 재사용으로 만료 시간이 늘어나지는 않습니다. 결과 파일과 제목·영상 ID·출력 옵션을 로컬 manifest에 저장하며 사용자 입력 URL 전체나 로그인 정보는 저장하지 않습니다.

브라우저 기능·속도 검사: `node scripts/fast-check.mjs "https://www.youtube.com/watch?v=영상ID"`. 설치된 Microsoft Edge가 필요합니다. 최초 메타데이터 조회 시간은 다운로드 버튼 클릭 이후의 측정에 포함되지 않습니다.

## 긴 영상 지원 (v1.3.0)

30분 길이 제한을 제거했습니다. 원본 합계와 결과 파일은 각각 2GiB(약 2.15GB)까지 처리하며, 화면·오류 안내에서는 편의상 2GB로 표시합니다. 크기가 큰 화질은 낮은 화질 또는 음원 저장을 선택하세요. 100MB를 넘는 파일도 메모리에 통째로 올리지 않고 디스크에 직접 스트리밍합니다.

긴 작업이 중간에 중단되지 않도록 수신/변환은 각각 60분, 전체 작업은 120분, 브라우저 상태 확인은 122분까지 허용합니다. 원본/결과 길이를 검사하여 파일이 잘린 상태로 완료 처리되지 않도록 합니다. 5분 메타데이터 캐시가 만료되면 작업 요청 시 공개 영상 정보를 다시 분석합니다.

임시 저장 공간은 작업별 최대 4GiB를 예약하고 전체 8GiB 안에서 제한합니다. 디스크 여유를 확인해 최소 2GiB를 남기도록 보수적으로 예약하며, 부족하면 507 오류로 안내합니다. 성공 후 원본 임시 파일은 즉시 삭제하고 결과는 위의 캐시 예산 안에서 보관합니다. 최대 동시 작업 수는 2개이며 디스크 예산에 따라 더 적게 허용될 수 있습니다.

긴 영상 실제 브라우저 검사: `node scripts/long-check.mjs "https://www.youtube.com/watch?v=영상ID"`. 30분 초과 영상의 최고 제공 화질, 원본 음원, MP3 전체 파일을 내려받아 길이·코덱·100MB 초과 결과 및 모바일 화면을 검사합니다. 실제 큰 파일을 수신하므로 네트워크·디스크 공간이 필요합니다.

특정 영상 화질만 검사하려면 `--mp4-only --quality=720`을 추가합니다. MP3는 디코딩과 재인코딩이 필요하므로 긴 영상일수록 처리 시간이 늘어날 수 있습니다.
